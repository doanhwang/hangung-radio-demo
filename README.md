```

│   └── P10_executive/              ← 경영자 리포트 라디오
└── logs/                           ← 생성 리포트 JSON
```

## 2. 파일 명명 체계

```
HANGUNG_{프로그램}_{에피소드}_{구간}_{날짜}_{버전}.mp3
```

| 구성 | 값 | 예시 |
|------|-----|------|
| 서비스 식별자 | HANGUNG (고정) | HANGUNG |
| 프로그램 | P01~P10 | P01 |
| 에피소드 | EP001~EP999 | EP001 |
| 구간 | S1~S5, FULL | S1 |
| 날짜 | YYYYMMDD | 20260606 |
| 버전 | v1, v2... | v1 |

**예시:**
- `HANGUNG_P01_EP001_S1_20260606_v1.mp3` → 칭찬라디오 1화 오프닝
- `HANGUNG_P01_EP001_FULL_20260606_v1.mp3` → 칭찬라디오 1화 합본
- `HANGUNG_P09_EP001_S2_20260606_v1.mp3` → 총재메시지 1화 사연소개

## 5. 빠른 시작 (Quick Start)

### 설치

```bash
pip install openai pydub
```

### 환경변수 설정

```bash
export OPENAI_API_KEY="sk-..."
```

### 데모 세트 생성 (투자유치용)

```bash
cd hangung_radio
python scripts/generate_mp3.py --mode demo --tts openai
```

### 단일 에피소드 생성

```bash
python scripts/generate_mp3.py --mode single --program P01 --episode EP001
```

### 현황 확인

```bash
python scripts/catalog.py --report
python scripts/catalog.py --scale     # 운영 규모 시뮬레이션
python scripts/catalog.py --export csv  # 스프레드시트용 내보내기
```

## 8. 각 방송의 사연 vs CM송 구분

```
story_song       = 회원 사연 기반 AI 생성 노래 (S4 구간)
cm_song          = 광고용 노래 (완전 별도 시스템)
broadcast        = DJ 멘트 + 사연소개 + 노래소개 + 노래재생 + 클로징 전체
```

**중요**: story_song을 cm_song이라고 부르는 것은 절대 금지.
회원 경험과 광고 상품이 섞여버림.

## 9. 투자자 프레젠테이션 활용법

1. **P01 EP001 FULL** 파일 → 회원용 서비스 시연
2. **P03 EP001 FULL** 파일 → 가족 공유/자녀 결제 시연
3. **P06 EP001 FULL** 파일 → 지도사 교육 시스템 시연
4. **P09 EP001 FULL** 파일 → 총재 브랜딩/비전 시연
5. **P10 EP001 FULL** 파일 → 경영진 리포트 시스템 시연

이 5개 파일로 전체 생태계의 작동 방식을 15분 내 설명 가능.
